# Architecture Overview, Feature Proposals & Quality-of-Life Improvements

## Architecture Snapshot
The application is a local-first Next.js 14 visual editor and architectural viewer for `.mmd` files and `.md` documents with embedded Mermaid diagrams:
- **Model & Surgical Transforms**: [`parseModel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L387-L450) in [model.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts) parses sequence and flowchart statements with exact line spans, and [editor.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/editor.ts) performs byte-preserving text transformations alongside the `%% CONFIG:` JSON header ([views.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/views.ts)).
- **Preprocessing & Domain Merging**: [`transformActors`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/preprocessor.ts) and [`processMermaid`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/preprocessor.ts) handle `%% @region-start` stripping, syntax cleanup, and 3-tier tag/subgraph collapsing (`On`, `Merged`, `Clean`, `Off`).
- **Interactive Canvas & Document Surface**: [`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx#L374-L435) maps SVG DOM nodes back to raw model keys via [`buildSelectionMap`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/svgmap.ts), supporting drag-to-connect, endpoint retargeting, FLIP animations ([`animateMovedElements`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx#L335-L372)), and sticky notes ([StickyNote.tsx](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/StickyNote.tsx)). [`WYSIWYGEditor`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/WYSIWYGEditor.tsx#L41-L201) provides block-level inline Markdown editing with embedded diagram previews.

## 🚀 6 Suggested Features

### 1. Visual Creation & Editing of Sequence Notes (`Note over / left of / right of`) and Blocks (`alt`, `loop`, `opt`, `rect`)
- **Why**: Currently, [`parseModel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L42-L72) parses [`NoteElement`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L42-L46) and [`BlockElement`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L68-L72), and [`NoteFields`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L896-L1013) in [EditorPanel.tsx](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx) allows tagging a native sequence note, but its text and spanned actors are read-only (`<p className="text-xs ...">{element.text}</p>`) and cannot be deleted or created from the UI. Meanwhile, [`BlockElement`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L68-L72) falls through to `"This element is not editable"` ([EditorPanel.tsx](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L300-L304)).
- **What to build**:
  - Make [`NoteFields`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L896-L1013) editable (note text, placement `over`/`left of`/`right of`, participant span, and deletion) + add an **"Add Sequence Note"** action in the toolbar.
  - Allow Shift-selecting contiguous messages on the canvas to wrap them in an `alt`, `opt`, `loop`, `par`, or `rect` block—or wrap them in a `%% @region-start: flow=...` region directly from [`MultiElementFields`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L361-L445) (similar to how `Group into Box` works for participants).

### 2. Step-by-Step Interactive Flow Player ("Walkthrough / Debugger Mode")
- **Why**: The app already has chronological animated arrows ([`BottomAnimatedArrowBar`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/BottomAnimatedArrowBar.tsx)) and `autonumber` support ([`toggleNumberedSteps`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/editor.ts)), and its core mission is helping teams present and trace 50+ flow diagrams.
- **What to build**:
  - A presentation/stepping bar (`Prev Step`, `Play/Pause`, `Next Step`, or `←`/`→` arrow keys) that steps through sequence messages or flowchart paths one message at a time.
  - Dim future messages (`opacity: 0.2`), auto-pan/zoom the [`TransformWrapper`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx#L1338-L1341) to follow the active step, and display any associated `Note over` or attached [`StickyNote`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/StickyNote.tsx) for that step.

### 3. First-Class Diagram Insertion & Creation in the Markdown WYSIWYG Editor
- **Why**: In [`WYSIWYGEditor`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/WYSIWYGEditor.tsx#L70-L80) and [`WYSIWYGBlock`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/WYSIWYGBlock.tsx#L204-L224), clicking `+` between Markdown blocks only inserts a text block (`paragraph`, `heading`, `list`, `quote`, `code`), and creating a new file in [`ClientPage`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1726-L1745) only creates `.mmd` files. To add a new Mermaid diagram to a `.md` document, a user currently has to manually type ```` ```mermaid ```` fences inside a code/text block.
- **What to build**:
  - Add **"+ Sequence Diagram"** and **"+ Flowchart"** options to the inter-block [`InsertButton`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/WYSIWYGEditor.tsx#L204-L228) in [`WYSIWYGEditor`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/WYSIWYGEditor.tsx) that scaffold a valid ```` ```mermaid ```` block and optionally open it right into the visual diagram editor.
  - Extend the `+ New` file dialog in [`ClientPage`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1726-L1745) to also create `.md` architecture documents.

### 4. Flowchart Parity: Edge Endpoint Retargeting & Subgraph Grouping (`subgraph ... end`)
- **Why**: Sequence diagrams support dragging message arrowheads/tails to retarget endpoints ([`moveMessageEndpoint`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/editor.ts) and [`endpointHitAt`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx#L190-L212)) and Shift-clicking participants to wrap them into a `box` ([`groupParticipants`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/editor.ts)). Flowcharts lack both: flowchart edges cannot be retargeted by dragging their endpoints, and [`MultiElementFields`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L374-L430) filters strictly for `el.kind === 'participant'`, so Shift-selected flowchart nodes (`el.kind === 'node'`) cannot be grouped into a `subgraph` block via the UI.
- **What to build**:
  - Expose head/tail drag handles on selected flowchart edges in [`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx) and implement `moveEdgeEndpoint` in [editor.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/editor.ts) (preserving chained edges via [`parseFlowchartLine`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L236-L355)).
  - Enable **"Group into Subgraph"** in [`MultiElementFields`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/EditorPanel.tsx#L361-L445) when 2+ flowchart nodes are Shift-selected, automatically leveraging the existing zero-config subgraph tag pipeline ([subgraphTags.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/subgraphTags.ts)).

### 5. Bidirectional Selection & Cursor Sync in Split View (Canvas ↔ Monaco Editor)
- **Why**: In Split View ([`SourceCodePanel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/SourceCodePanel.tsx) alongside [`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx)), canvas edits briefly flash green line diffs via [`changedLines`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L194-L214), but **selecting** an element on the canvas does not reveal its line in Monaco, and moving the cursor to a line in Monaco does not highlight or pan to that element on the canvas.
- **What to build**:
  - **Canvas → Code**: When `selectedRawElement` changes in [`ClientPage`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1104), use its exact [`lineStart` / `lineEnd`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L8-L13) to call `editor.revealLineInCenter()` and apply a subtle active-selection line decoration in [`SourceCodePanel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/SourceCodePanel.tsx).
  - **Code → Canvas**: Listen to `onDidChangeCursorPosition` in Monaco, map the cursor line back to the matching [`ModelElement`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L96-L98), highlight it on the SVG canvas, and provide a quick action (`Cmd/Ctrl+Click` or gutter icon) to center the canvas on that element.

### 6. Visual Git Diff Mode for Architecture Reviews
- **Why**: As highlighted in [README.md](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/README.md#L50-L56), plain-text `.mmd` files live in Git, yet reviewing a 2,000-line Mermaid diff in a PR still forces engineers to mentally parse raw text. The codebase already has [`computeLineDiff`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/sourceDiff.ts), [`parseModel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L387-L450), and SVG post-processing in [styling.ts](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/styling.ts).
- **What to build**:
  - Add an API endpoint (`/api/git-diff?file=...&ref=HEAD`) that retrieves the baseline version of the current `.mmd` or `.md` file from Git.
  - Compare baseline and current [`DiagramModel`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/model.ts#L100-L103) elements and render a **Visual Diff Overlay** on the canvas: newly added participants/nodes/arrows highlighted in emerald, modified labels/operators badged in amber with a hover tooltip showing the previous value, and removed elements optionally shown as dimmed crimson ghost elements.

## ✅ Implemented QoL Improvements

### 1. Keyboard Shortcuts for Canvas Operations (`Delete`/`Backspace`, `Escape`, and `Cmd+Shift+Z`) — DONE
- `Delete`/`Backspace` triggers the same delete as the panel's Delete button ([`handleRequestDelete`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx) — cascade confirmation included), skipped inside text fields and while visual edits are locked. `Escape` clears the canvas selection, or cancels an active canvas drag mid-flight ([`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx) cancels the drag and marks the event handled so the selection survives). The undo/redo listener now accepts `Shift` for `z`, so macOS-standard `Cmd+Shift+Z` redoes. Covered by unit tests (`ClientPage.test.tsx`, `DiagramViewer.test.tsx`) and `cypress/e2e/canvas-shortcuts.cy.ts`.
- Also fixed while testing this: an undo+redo back to the last-written content inside the 800 ms auto-save debounce window left the save indicator stuck at "Saving…" — the superseded save's timer was cleared but its status never settled.

### 2. Zoom Controls Toolbar & "Fit to Screen" / Search Result Auto-Pan — DONE
- A floating bottom-left canvas pill ([`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx)) gives **Zoom Out / level / Zoom In** (absolute ±0.5 steps, clamped to 20%–800%, buttons disable at the bounds) and **Fit to Screen**, which scales the whole SVG into the viewport via `zoomToElement` (capped at 100%, so small diagrams are never blown up). Double-click-to-zoom is disabled so double-click can open the inline label editor instead.
- While a search query is active, the pill gains **Prev/Next match** buttons and an `n/total` counter; matches are highlighted red/bold on the SVG and the canvas auto-pans to center the active match at a readable zoom (never below 100%), wrapping around at both ends. The query syncs to the URL (`?q=…`).
- Also fixed while testing this: the SVG host `<div>` re-created its `dangerouslySetInnerHTML` object on every render, and React diffs host props by identity at commit time — so **every** re-render re-applied `innerHTML` and replaced the whole SVG subtree, detaching the search-match elements (auto-pan became a no-op) and wiping their highlight. The object is now memoized on `[svgStr]`, so the SVG survives unrelated re-renders.
- Covered by unit tests (`DiagramViewer.test.tsx`) and `cypress/e2e/zoom-controls.cy.ts`.

### 3. Double-Click Inline Label Editing on the Canvas — DONE
- Double-clicking a participant box (top or bottom, box or stick figure), flowchart node, or message/edge label on the SVG canvas opens a floating `<input>` directly over the clicked element's label (`[data-testid="inline-label-editor"]` in [`DiagramViewer`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/DiagramViewer.tsx)), sized to the label's screen rect and font-matched to the on-screen text size, so it stays aligned at any zoom. `Enter` or clicking away commits; `Escape` cancels; an unchanged label is not reported.
- The new [`labelElementForKey`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/svgmap.ts) helper in `svgmap.ts` resolves the label element for a processed key (preferring the actually-clicked visual, e.g. a bottom actor box), and [`ClientPage`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx) maps the processed key back to the raw element through `buildSelectionMap` and runs the same `renameParticipant` / `editMessageLabel` → `applyEditResult` pipeline as the properties panel — so the `.mmd` rewrite, undo stack, and auto-save behave identically. Notes and sticky notes are excluded (sticky notes keep their own double-click editor); the editor only opens in edit mode and not while visual edits are locked.
- Also fixed while testing this: `react-zoom-pan-pinch` `preventDefault()`s mousedown while panning, so clicking the canvas never blurred the input — the canvas now commits the open editor on mousedown (capture phase).
- Covered by unit tests (`svgmap.test.ts`, `DiagramViewer.test.tsx`, `ClientPage.test.tsx`) and `cypress/e2e/inline-label-edit.cy.ts`.

## ✨ 2 Remaining Quality-of-Life (QoL) Improvements

### 1. Replace Native `window.prompt` / `window.confirm` in Saved Views & Add "Update Active View"
- **Current gap**: [`saveCurrentView`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1777-L1812) uses `window.prompt('Enter view name:')` and [`deleteView`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1814-L1835) uses `window.confirm(...)`, whereas `New Diagram` and `Delete Element` use styled inline modals. Furthermore, if you load a saved view, tweak a filter, and want to update that view, you have to click Save and manually re-type the exact view name into `window.prompt`.
- **Fix**: Replace the browser prompts with an inline popover/input, and show a 1-click **"Update View"** button on the active view when filter state diverges from the saved view.

### 2. PNG / Clipboard Image Export alongside SVG Export
- **Current gap**: [`exportSvgToFile`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/lib/svgExport.ts) exports a standalone `.svg` file, and [`handleCopyMermaid`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L1409-L1430) copies raw Mermaid syntax. However, pasting diagrams into Slack, Jira, Google Docs, or PR comments usually requires a high-DPI PNG image on the clipboard (`Copy as PNG` / `Export PNG`).
- **Fix**: Add a **"Copy PNG" / "Export PNG"** option next to [`Export SVG`](file:///Users/zlatinstanimirov/code/mermaid-sequence-viewer/src/components/ClientPage.tsx#L2530-L2543) that renders the serialized SVG onto an offscreen `<canvas>` (at `2x` scale) and writes it to `navigator.clipboard.write` or downloads a `.png`.
